## Correct reuse strategy

The pipeline should be **reconcile-first**, never blindly resend.

Priority order:

1. Exact prior result for the same request fingerprint exists and is valid → **reuse it**.
2. Existing generated result for the same panel/source/anchor/prompt revision exists → reconcile and restore it.
3. Existing panel crop attachment exists → use that exact provider-side crop as generation reference.
4. Original source attachment + bbox → fallback only if no panel crop exists.
5. Upload new bytes only when the conversation truly has no reusable source asset.

## Required product behavior

Introduce a **conversation asset index** keyed by:

- conversation id
- source asset identity
- panel index
- panel crop provider identity
- visual-anchor revision
- prompt revision
- output provider pointer / local artifact hash
- validity / approval state

Before any image request:

1. query the cached conversation asset index;
2. restore a valid previous result when available;
3. otherwise choose the narrowest existing provider-side source asset;
4. only then permit a new generation request;
5. never resend the same generation intent without an explicit force/regenerate action.

## Engineering rule

GitHub is the source of truth for project edits. Project code/research files should be created or updated through the GitHub workflow first. Local checkouts are execution/test workspaces that consume committed GitHub state, not the primary editing surface.
